## UxAir playback and limits

- The Starfish development build handles /play independently from RTP screen mirroring. The adapter retains PTTH, event publishing, bounded plist parsing, playback feedback and the existing UxPlay discovery responses. It correlates FCUP responses to the active owner's request ID and URL. With the developer FCUP switch enabled it can request an HTTP(S) manifest through PTTH after a permitted destination returns 403 or 404. Ordinary successful HTTP(S) retrieval makes no FCUP request. Sender-specific non-HTTP URI schemes are outside this experiment.
- In auto mode, Starfish URI playback gets one attempt through a tokenized loopback relay. A successful segment GET, advancing native playtime and video information or a frame callback establish observable startup. Failed startup can switch once to BUFFERSTREAM after native cleanup succeeds. A failed native unload blocks decoder reuse until app restart. A firmware call that blocks on the application thread remains a separate failure class, with begin/end diagnostics and a hard process deadline in the isolated probe.
- BUFFERSTREAM selects one compatible muxed H.264/AAC variant, reads its VOD TS segments with FFmpeg custom AVIO and feeds Annex B H.264 in decode order with the presentation timestamps expected by the existing Starfish API. AAC-LC ADTS is decoded through the existing audio decoder and resampled to 44.1 kHz stereo PCM on the same timeline. An eight-MiB fetch cap and one prepared segment slot bound work ahead of playback. Seek restarts at the preceding independently decodable segment. Live HLS, fMP4/CMAF, external audio groups, encryption and timestamp discontinuities are outside BUFFERSTREAM's supported scope. The Native URI diagnostic can exercise selected additional formats. Device video, audible playback, sync, transport controls and Safari interoperability require B7 testing.
- Network fetching uses pinned curl/OpenSSL, verified TLS, IPv4 socket address checks and redirect and I/O deadlines. DNS changes are checked again at the socket. FFmpeg has no network protocols enabled and receives only bytes fetched by UxAir. Production and NDL builds omit the Direct Video implementation and discovery.
