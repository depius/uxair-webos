# Minimal pre-release security hardening

Scope: pre-release hardening on fix/pr10-b7-compatibility. This document records implemented defenses, tests and remaining technical limitations.

## Confirmed fixes

- NDL upgrades with existing legacy app-local state and no var/lib state now fail closed before creating new storage. This preserves old keys/settings instead of silently initializing a different identity. No automatic migration, ownership relaxation or installation-directory chmod was added. Existing NDL var/lib storage and fresh installations retain their selection policy; Starfish is unchanged. A separately approved secure migration is required for that legacy NDL case.

- Production UxPlay mirroring previously allocated a sender-declared signed size before Receiver::enqueue applied its ceiling. tools/harden-network.py checks the exact pinned upstream blobs and generates bounded copies for both production backends. Raw mirrored payloads are limited to the existing largest ingress ceiling (2 MiB), negative lengths are rejected, prepend sums are checked without signed overflow, and allocation failures trigger the existing transport-failure cleanup rather than dereferencing NULL or exiting the process. Parameter-set allocations are also checked. Codec parsing, packet/frame queues, scheduling, feed timeouts and media implementations are unchanged. These wire bounds do not increase any profile's accepted packet size.
- Production HTTP bodies now receive the existing development ceiling of 32 MiB before realloc, with cumulative-size/overflow validation and safe preservation of the previous allocation on failure. The development HTTP transform uses the same guard and keeps its existing sanitized diagnostic.
- tools/ipk_permissions.py normalizes packaged internal lib/licenses directories to 0755, metadata/data to 0644 and the two ELF files to 0755. Both packaging paths and both receiver targets use it; validate-ipk.py checks the policy. File contents, app ID, version and archive owners are preserved. Links, special files, unsafe paths and duplicate members are rejected.
- The full packaging npm dependency graph is recorded in tools/webos-cli/package-lock.json. CI uses npm ci --ignore-scripts rather than a global ranged installation. This disables dependency lifecycle scripts, including the CLI's world-writable configuration chmod postinstall. CLI 3.2.6 is unchanged. The upstream tarball itself also contains npm-shrinkwrap.json: the earlier audit's description of an entirely unlocked transitive graph was too broad. The project now retains the resolved graph explicitly and disables lifecycle execution; this does not reconstruct earlier runs or attest that dependencies are benign.
- Corresponding-source packaging excludes installed node_modules and Python caches while retaining the package and lock manifests. No host packaging executables are added to the TV package or source archive.

Tests exercise generated C allocation sites under ASan/UBSan, exact limits, limit-plus-one, negative and overflow inputs, allocation failure without process exit, unchanged old-buffer ownership, altered pinned-source refusal, real IPK creation/permission normalization with byte-identical payloads, managed-container preservation, unsafe entries and source archive exclusion. CI builds Starfish and NDL separately and uploads no artifacts.

## Deliberate limits and remaining risks

1. The B7's webOS-managed installation container remains writable and is not chmodded by this change. Jailed UID 5999 must be able to create its private state under a differently owned container. Internal permissions reduce direct writable-library/metadata exposure, but a process able to rename children through the writable ancestor can still replace binaries/directories or interfere with state paths. This is not a complete local-attacker isolation boundary. Changing that boundary requires a platform-supported storage/install ownership plan and fresh/upgrade physical tests; no UID whitelist or /tmp identity fallback was added.
2. Pinned upstream malformed-media parsing beyond allocation sites still needs a separate focused review. In particular, production parameter-set/NAL parsing does not receive the development parser rewrite. Bounded allocations are not proof that every upstream read or copy is in bounds. No claim of remote code execution was established by the original audit, and this change is not a complete protocol security audit.
3. The npm lock/integrity checks and disabled scripts improve input control; a registry audit still reports 18 affected host package entries (1 critical, 4 high, 13 moderate). See [PACKAGING_DEPENDENCY_AUDIT.md](PACKAGING_DEPENDENCY_AUDIT.md) for reachability and primary advisory references. Package-only CI starts no CLI HTTP server; these findings are not declared fixed. Runner images, apt packages and timestamps are not fully pinned. No independent reproducible-build comparison, SBOM/attestation or publisher-signature verification has been completed.
4. The executable remains non-PIE with partial loader hardening. Do not change loader flags speculatively on old B7 firmware. Proprietary Starfish/ACB/NDL and firmware libraries are outside this audit.
5. The owner accepted the exact hardened Starfish candidate on the B7. The report did not specify a fresh-install and upgrade matrix. NDL is Beta / Experimental with no current-build physical validation. See the [B7 acceptance record](B7_FINAL_TEST.md).

The pre-hardening physical baseline and its TEST IPK are preserved unchanged. Publication requires separate owner approval.
